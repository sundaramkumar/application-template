# Architecture & Conventions

This document is the source of truth for how the codebase is structured. Keep it
current — humans and AI assistants both rely on it. For the big-picture mental model
first, read [OVERVIEW.md](./OVERVIEW.md).

## Monorepo (Bun workspaces)
```
application/backend   application/frontend   application/shared
```
- `@shared` resolves to `application/shared/src` via tsconfig `paths` + Vite alias (and is a
  Bun workspace package, `@application/shared`).
- Run everything from the repo root via `bun run --filter '*' <script>` wrappers
  (`dev`, `typecheck`, `build`, `lint`, `db:migrate`, `seed`).

## Backend (`application/backend/src`)
Feature-based, layered. Each feature folder under `features/<name>/`:

| File | Responsibility |
|---|---|
| `<name>.routes.ts` | Hono router; attaches `zValidator('json', schema, zHook)`. No logic. |
| `<name>.controller.ts` | HTTP layer: read params/body, call **one** service fn, return via `lib/response`. Thin. |
| `<name>.service.ts` | All Drizzle queries + business logic. Throws `AppError`s. Returns domain objects. |

Shared infra:
- `app.ts` — Hono app, CORS, auth middleware, `PUBLIC_PATHS`.
- `routes.ts` — mounts feature routers under `/api`.
- `config/env.ts` — Zod-validated environment.
- `db/index.ts` — Drizzle over `Bun.sql`; `withTransaction()` helper.
- `db/schema/*` — `pgTable` definitions; re-exported from `db/schema/index.ts`.
- `db/migrations/*` — generated by drizzle-kit (committed).
- `lib/` — `response` (ok/created/paginated/noContent), `errors` (`AppError` + helpers),
  `db-errors` (Postgres unique-violation detection), `list-query` (pagination parsing),
  `zhook` (turns Zod failures into `AppError`), `logger`.
- `middleware/` — `auth` (JWT cookie → `c.get('user')`), `request-logger`, `error-handler`.

### Validation
Request schemas live in **`@shared/schemas`** (plain Zod 4) and are used by both the
backend (`zValidator`) and the frontend (`react-hook-form` + `zodResolver`). One schema,
both sides. Drizzle-derived validation is intentionally not used here because it can't
cross the FE/BE boundary.

### Auth
- `POST /api/auth/login` verifies bcrypt + issues a `jose` JWT in an **httpOnly** cookie
  (`app_token`). `GET /api/auth/me`, `POST /api/auth/logout`.
- `authMiddleware` guards everything except `PUBLIC_PATHS`.
- Secrets/cookies: `secure` cookie in production; `JWT_SECRET` ≥ 32 chars.

### DB conventions
- **Primary keys:** UUID on every table — use `uuidPk()` from `db/schema/_columns.ts`
  (app-generated UUID v7, `gen_random_uuid()` DB default). Reference columns
  (`*_id`, `created_by`, `updated_by`) are `uuid`. Validate route/query ids with
  `paramId` / `queryId` and read the actor with `actorIdOf` (`lib/ids.ts`); the
  frontend parses `:id` with `parseRouteId` (`shared/lib/ids.ts`).
- **Audit:** `created_by` / `updated_by` set from the JWT actor; `created_at` / `updated_at`.
- **Soft delete:** `deleted_at` timestamp. List/get/login filter `deleted_at IS NULL`.
  Uniqueness uses **partial unique indexes** (`WHERE deleted_at IS NULL`) so a deleted
  row's username/email can be reused.
- **Transactions:** wrap multi-step writes in `withTransaction`.
- **Migrations:** change `db/schema`, then `bun run db:generate` → review SQL → `bun run db:migrate`.

### Pagination / list endpoints
Use `parseListQuery(c, { sortable, defaultSort })` (whitelisted sort columns) and return
`paginated(c, data, buildMeta(total, page, limit))` → `{ data, meta: {page,limit,total,totalPages} }`.

## Frontend (`application/frontend/src`)
Feature-based mirror under `features/<name>/{api,screens}`. Shared in `shared/`:
- `api/client.ts` — `apiFetch` (cookies via `credentials: 'include'`, central error mapping).
- `components/ui` — DataTable, Modal, Select, Input, ConfirmDialog, Tooltip…
- `components/ErrorBoundary.tsx` — wraps routed content; a screen crash won't kill the app.
- `config/nav.config.ts` — single source for nav items + routes.
- State: TanStack Query for server state; Zustand (`features/auth/store`) for the session.
- Forms: `react-hook-form` + `zodResolver(<shared schema>)`.
- List screens: `DataTable` in `serverSide` mode wired to the paginated API.

## Adding a feature (checklist)
1. **Shared:** add types in `shared/src/types/<name>.types.ts`; request schemas in
   `shared/src/schemas/<name>.schema.ts`; export both from `shared/src/index.ts`.
2. **DB:** add `db/schema/<name>.ts` (+ audit/soft-delete columns), export it, then
   `bun run db:generate && bun run db:migrate`.
3. **Backend:** `features/<name>/{routes,controller,service}.ts`; mount in `routes.ts`.
   Validate with the shared schema via `zValidator(..., zHook)`.
4. **Frontend:** `features/<name>/api/<name>.api.ts` + `screens/<Name>.tsx`; add a
   `nav.config` entry + `App.tsx` route. Forms use react-hook-form + the shared schema.
5. `bun run typecheck` before committing.
